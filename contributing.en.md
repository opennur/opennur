# Contributing to OpenNur

**Bismillahirrahmanirrahim.**

Thanks for wanting to contribute to **OpenNur Project** — a digital waqf project building open-source Islamic software.

Contributions come in many forms: code, design, content, review, testing, donations, prayers, even ideas. This doc is just a guide to keep things running smoothly.

---

## 🌱 Core Principles

1. **Intention for Allah**  
   Contributing here is an act of ongoing charity — not for showing off, popularity, or worldly gain.

2. **Open and Collaborative**  
   Anyone can contribute regardless of background, as long as you follow the guidelines.

3. **Respect Knowledge and Scholars**  
   Islamic content must be sourced from authoritative references (Quran, authentic hadith, recognized scholarly works). Don't make baseless claims.

4. **Trustworthy and Transparent**  
   No hidden agendas, no inserting malicious code, ads, or trackers that harm users.

---

## 💻 How to Contribute (Developers)

### 1. Fork the Repository
- Go to the repo you want to work on, like [Tahsin Qur'an](https://github.com/opennur/tahsin).
- Click **Fork** in the top right to create a copy on your GitHub account.

### 2. Clone the Repository
```bash
git clone https://github.com/your-username/repo-name.git
cd repo-name
```

### 3. Create a New Branch
Use a descriptive branch name, like `feature-tajweed-color` or `fix-notification-crash`.
```bash
git checkout -b your-feature
```

### 4. Make Changes
- Follow the existing code style.
- Write enough comments to make review easier.
- Make sure no temp files or build artifacts get committed.

### 5. Commit with a Clear Message
Use short, descriptive commit messages like:
```
feat: add tajweed coloring in mushaf mode
fix: fix crash when opening Surah Al-Baqarah
docs: update installation guide
```

### 6. Push and Create a Pull Request
```bash
git push origin your-feature
```
- Open your forked repo on GitHub.
- Click **Compare & pull request**.
- Briefly explain what you changed, why, and include screenshots if relevant.
- PRs will be reviewed by maintainers. Please be patient and open to feedback.

## 🎨 How to Contribute (Non-Developers)

### UI/UX Designers
- Create mockups, icons, illustrations, or visual assets.
- Suggest interface improvements for better usability.
- Design files go in the `design/` folder or submit via issues/discussions.

### Content Writers & Translators
- Prepare learning materials (Arabic lessons, tajweed quizzes, vocabulary, etc).
- Translate interface text or content to other languages.
- Make sure every material includes source references.

### Religious Scholars / Students of Knowledge
- Review Islamic content: tajweed, tafsir, hadith, fiqh, supplications.
- Provide corrections or validation on features related to Sharia.
- Can contribute via issues, pull requests, or discussions.

### Testers / Users
- Download and try the app.
- Report bugs or unexpected behavior through **Issues**.
- Suggest improvements and new features.
- Spread the word about OpenNur to others.

### Donors
- Support operational and development costs through [Tako](https://tako.id/opennur) or [Ko-Fi](https://ko-fi.com/opennur).
- Funds are recorded transparently and used for the project's benefit.

## 📋 Islamic Content Guidelines

Since this project directly relates to Islamic teachings, there are some rules:

1. **Primary Sources**  
   - Quran: use the standard mushaf (Hafs 'an 'Ashim narration) and official translations (e.g., Kemenag RI).  
   - Hadith: prioritize authentic hadith collections (Bukhari, Muslim, Abu Dawud, Tirmidhi, Nasai, Ibn Majah, etc.). Include hadith numbers and authenticity grades when known.  
   - Tafsir: reference recognized tafsir works like Tafsir Ibn Kathir, Tafsir As-Sa'di, Tafsir Al-Qurthubi, etc.  
   - Fiqh: reference standard fiqh books from recognized schools or credible institutional fatwas.

2. **Avoid**  
   - Opinions that deviate from Ahlus Sunnah wal Jama'ah.  
   - Content containing bid'ah, superstitions, or baseless claims.  
   - Unproductive sectarian debates — if there are differences of opinion, present them objectively with references.

3. **Content Verification**  
   - Output from modern technology tools (translations, explanations, quizzes, etc.) **must be verified** by competent humans before being included in the app.  
   - Technology is an aid, not a source of ruling.

## 🧭 Communication Etiquette

- Be polite, friendly, and professional.
- Respect all contributors regardless of background.
- No personal attacks, hate speech, or unhealthy arguments.
- If there are disagreements, present them with evidence and good manners.
- Remember, we're all trying to do good deeds — don't let differences ruin brotherhood.

## 🐞 Reporting Bugs or Suggesting Features

Open an **Issue** on the relevant repository. To make things easier, use this template:

**Issue Title:**  
`[Bug] App crashes when opening Surah Al-Baqarah`

**Description:**  
- **App version:** (e.g., v1.2.0)  
- **Device:** (e.g., Samsung A51, Android 12)  
- **Steps to reproduce:**  
  1. Open the app  
  2. Select Surah Al-Baqarah  
  3. Scroll to ayah 255  
  4. App suddenly closes  
- **Expected result:** App continues running normally  
- **Screenshot/log:** (if available)

For feature requests, explain the benefit to users and, if possible, how to implement it.
